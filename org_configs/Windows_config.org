* 使用与维护

** 配置生成

本文件是配置源文件，Emacs Lisp 代码块会生成到仓库根目录的 =init.el=。
生成路径相对于本 Org 文件，因此 =../init.el= 指向上一级目录。
请修改本文件，再重新生成，不要直接修改生成的 =init.el=。
本配置不提供依赖固定 Org 文件名的生成函数。以后将文件改名为 self.org 等名称，
只要头部的相对生成路径仍正确，就可在该文件中直接调用 org-babel-tangle。
如果移动文件到其他目录，需要同步调整头部的 :tangle 路径；命令行示例中的源文件路径也需更新。

保存文档、生成配置、加载配置是三件不同的事：

| 操作                                  | 改变什么                         | 不会做什么                 |
|---------------------------------------+----------------------------------+----------------------------|
| 保存 Org；toc-org 更新目录             | Org 文件及其中的目录链接         | 不会自动生成或加载 init.el |
| C-c C-v t；org-babel-tangle             | 按代码块顺序生成 init.el         | 不会自动加载新配置         |
| 重启 Emacs；或按需 load-file           | 执行 init.el，应用配置           | 不会修改 Org 源文件        |

日常维护顺序：修改 Org → 保存 → 生成 → 检查差异 → 重启验证。
所有配置改动以本 Org 文件为源头，init.el 仅通过 tangle 更新，不手工维护两份代码。
Emacs 自定义界面的持久化状态单独保存在 custom.el，不再追加到生成文件末尾。
在 Emacs 中打开本文件，按 =C-c C-v t=，或执行 =M-x org-babel-tangle RET= 生成配置。
有 Git 基线时，可在仓库根目录执行 =git diff -- org_configs/Windows_config.org init.el=
检查源文件和生成结果；尚未提交的全新文件也需要直接检查内容。

简单参数变更可以用 =M-x load-file RET= 选择生成的 =init.el= 进行试验，
但重新加载不等于全新启动：从源文件删除 hook、键位或模式启用代码，
不会自动撤销旧会话里已生效的设置。调整加载顺序、删除配置或修改模式启用方式后，
以重启验证为准。例如删除编号 hook 后，旧会话可能仍保留它，重启才能确认新默认行为。

也可以在仓库根目录使用命令行生成：

#+begin_src sh :tangle no
emacs -Q --batch --load org --eval '(org-babel-tangle-file "org_configs/Windows_config.org")'
#+end_src

*** 代码块编辑、执行与生成

| 写法或操作                    | 含义                                                   |
|-------------------------------+--------------------------------------------------------|
| begin_src emacs-lisp           | Lisp 代码块，按本文件头部属性默认参与生成                |
| :tangle no                    | 不参与生成；仍可手动执行，不代表禁止执行                 |
| begin_example                 | 纯说明示例，不是可执行的 Babel 代码块                    |
| 代码块内 C-c '                | 在专用编辑缓冲区编辑代码；完成后再按 C-c ' 返回           |
| 代码块内 C-c C-c              | 通常执行当前代码块，与生成 init.el 不同                  |
| C-c C-v t                     | 提取代码生成文件，不执行这些 Lisp 表达式                 |

本文件通过 =header-args:emacs-lisp :tangle ../init.el= 指定生成位置。
生成时按源文件中代码块的出现顺序拼接，因此移动代码块也可能改变初始化顺序。
标为说明示例的代码块不要当作已经启用的配置；是否参与生成，以块上的参数为准。

** 目录与大纲导航

Org 原生支持按标题组织内容，不需要目录插件。本文件设置了
=#+startup: overview num=，重新打开时默认显示顶层标题及自动章节号，便于先看结构。

| 操作                         | 按键或命令                                  |
|------------------------------+---------------------------------------------|
| 折叠／展开当前标题           | 光标位于标题时按 =TAB=                       |
| 切换全文概览、标题和完整内容 | =S-TAB=，或 =M-x org-shifttab=               |
| 搜索标题并跳转               | =C-c C-j=，或 =M-x org-goto=                 |
| 回到上一级标题               | =C-c C-u=                                   |
| 当前文档的标题索引           | =M-x imenu=                                 |
| 打开文档中的链接             | =C-c C-o=                                   |

上面是 Org 默认操作；本阶段已经写入 Evil / evil-collection 配置，
安装后的模式键位以手动体验和当前模式帮助为准，命令名仍可通过 =M-x= 调用。

=#+options: toc:4= 指定导出时自动生成最多四级标题的目录，
例如使用 =C-c C-e h h= 导出 HTML 时生效。它不会在编辑缓冲区自动插入目录文本，
因此文档开头另提供了可直接点击的章节链接。
这些链接由下面的 =toc-org= 配置在保存时自动更新，不需要手工维护。

*** “目录”后面的标签是什么

=* 目录 :TOC_4_org:= 的标题名称只有“目录”，后面的是 Org 标签，不属于标题文字。
=toc-org= 依靠该标签识别应该在哪个章节生成目录：

- =TOC=：这是目录生成位置；只写 =* 目录= 时插件不会识别。
- =4=：生成到四级标题，覆盖“个人配置”增加的一层。
- =org=：使用 Org 原生标题链接。

可以改成更短的 =:TOC:=，但它会使用插件默认的两级目录和 GitHub 风格链接。
本文件保留显式标签，让文件离开这套配置后仍能清楚表达目录深度和链接格式。

*** 章节索引与跳转

Org 内置的 =org-num-mode= 在标题前显示 =1=、=1.1=、=1.1.1= 等编号，
插入或移动章节时自动更新；这些编号是编辑器显示效果，不写入标题源文本。
目录的 =UNNUMBERED= 属性用于导出时排除编号；编辑器内是否跳过该标题，
由 =org-num-skip-unnumbered= 决定，本配置不再全局修改它。
导出时的 =num:4= 也会生成四级章节号；toc-org 目录仍按标题生成链接，
目录链接文字以及 org-goto / Imenu 的候选不自动带上 org-num 的显示编号。
需要跳转时使用目录链接、=org-goto= 或 Imenu；章节号用于阅读定位和沟通，
不是输入一个数字就自动跳转的命令。

*** Org 的行内标记

Org 的等号包围语法类似 Markdown 的反引号，用来区分普通文字和字面内容。
下面用示例块展示源文本，避免它们被直接显示成格式化文字：

#+begin_example
=org-goto=       字面文本（verbatim），适合命令名、路径、按键
~(message "Hi")~ 行内代码（code），适合代码片段
*加粗*           粗体
/强调/           斜体
_下划线_         下划线
+删除线+         删除线
#+end_example

等号和波浪号都常显示为等宽文本，内部不会继续按普通强调语法解释。
它们只是排版标记，不会执行内容；具体颜色和字体取决于主题，
标记符号是否隐藏则取决于 =org-hide-emphasis-markers=。
Markdown 的反引号不是 Org 默认的行内代码标记，所以本文使用等号来标出命令和路径。

** 启动时选择本配置目录

如果 =~/.emacs.d/= 已存在，Emacs 会优先使用该目录，因而不会自动
读取本仓库的 =~/.config/emacs/init.el=。即使旧目录只有缓存也会如此。
可以在仓库根目录显式指定配置目录启动：

#+begin_src sh :tangle no
emacs --init-directory . --user ""
emacs -nw --init-directory . --user ""
#+end_src

从其他目录启动时，将 =.= 替换为本仓库的绝对路径。
本机 Emacs 31.1 实测还需要 =--user ""=，否则仅修改了
=user-emacs-directory=，启动文件搜索仍然使用旧目录。
启动后可用 =M-: user-init-file RET= 查看实际读取的配置文件。

** 跨平台迁移

文件名保留 =Windows_config.org=，但当前生成的基础配置也按跨平台方式编写。
建议各平台使用 Emacs 29 或更新版本；目前实际验证环境是 Windows Emacs 31.1，
没有在 Linux / macOS 真机运行验证。

- Windows 默认使用系统可发现的 GPG；下面的 Git GPG 修复仅适用于已复现问题的本机环境。
- Linux / macOS 使用 Emacs PATH 中的 =gpg2= 或 =gpg=，需要自行安装 GnuPG。
  macOS 从桌面启动 Emacs 时，PATH 可能不包含 Homebrew 的程序目录，
  应先检查 =(executable-find "gpg")=；后续平台环境章节再处理路径继承。
- 代理是本机服务；其他电脑也需要相同端口的代理，或者修改／关闭下面的代理设置。
- 迁移源文件和生成的 =init.el=，插件和本地缓存应在目标系统重新生成，
  不要复制 =elpa/=、=eln-cache/= 或 GPG 运行目录。
- 自动识别配置目录仍受旧 =~/.emacs=、=~/.emacs.d/= 的影响；可显式使用
  前面的启动命令。macOS 需要使用实际安装的 Emacs 可执行文件。

Linux / macOS 不会执行本机特有的 Windows GPG 路径修复，因此不会因为这段配置
产生同样的盘符拼接问题。但缺少 GPG、PATH 不正确、公钥过期或缺失，仍可能造成
签名校验失败；不能保证任何系统都永远不会出现 GPG 错误。

** 故障排查入口

先确认“读的是哪份配置、失败在哪一步”，再按错误定位。
实际命令和表达式如下；这里是操作说明，没有增加自定义键位。

| 情况                         | 检查入口                                                |
|------------------------------+---------------------------------------------------------|
| 怀疑配置没有加载             | M-: user-init-file RET                                   |
| 查看启动或下载消息           | C-h e，或者切换到 *Messages*                             |
| 已启动，重现操作错误         | M-x toggle-debug-on-error，开启后重现以查看回溯           |
| 启动时配置报错               | 在启动命令中加 --debug-init                              |
| 找不到外部工具               | M-: (executable-find "gpg") RET；clangd、rg 同理           |
| 下载失败                     | 查看 url-proxy-services、package-archives 及具体错误      |
| 生成结果与预期不符           | 核对代码块 :tangle 参数、顺序和实际生成的 init.el          |
| 删除配置后旧行为仍存在       | 重启再验证，避免把旧会话状态当作新配置行为                |

例如在仓库根目录启动诊断：

#+begin_src sh :tangle no
emacs --init-directory . --user "" --debug-init
#+end_src

排查结束后可再次执行 =M-x toggle-debug-on-error= 关闭调试。
GPG 先查看实际可执行文件和错误路径；本机 MSYS2 路径问题的修复仅见包管理章节，
其他机器不直接套用本机特例，也不以关闭 TLS 或签名校验作为通用解决方式。

** 配置入口

软件包统一安装在本仓库的 =elpa/= 目录，不依赖启动时的工作目录。

** Custom 独立保存

Emacs 的 Customize 和软件包操作可能保存变量；未设置 custom-file 时，
它们可能把 custom-set-variables / custom-set-faces 追加到 user-init-file。
本仓库的 init.el 是生成物，因此必须将这些持久化内容与 Org 主配置分开。

下面在包管理与插件声明之前指定并读取仓库根目录的 custom.el。
它是本机状态文件，由 Emacs 管理，已加入 .gitignore；文件不存在时不报错，
后续通过 Customize 保存或软件包操作即可创建。长期功能配置仍写入 Org，
custom.el 中的同名设置不应当作优先于后续 Org 配置的覆盖层。

#+begin_src emacs-lisp
;;; Custom 状态独立保存，避免污染由 Org 生成的 init.el。
;; 尽早设置：首次安装插件时，包选择记录也应写到 custom.el。
(setq custom-file (expand-file-name "custom.el" my/config-directory))
(load custom-file 'noerror 'nomessage)
#+end_src

本次仅迁移 init.el.bak 中的 package-selected-packages 元数据，
没有恢复已删除的 init.el 尾部，也没有把备份中的任意代码整段载入。
这份包选择记录用于包管理，不等于插件已加载，也不定义 Evil 的内部变量。
以后重新生成 init.el 不会覆盖 custom.el；不要把本机密钥或令牌存进版本库。

** 网络代理

使用本地 HTTP 代理 =127.0.0.1:10808=。先设置代理，再访问软件源。
=http= 和 =https= 都通过同一个代理端口，访问本机地址则不走代理。
启动 Emacs 前，请先启动提供该端口的代理程序。

这里配置的是 Emacs URL 库的代理，适用于软件包下载等操作；
不会自动修改外部 Git、clangd 等程序的代理环境。
迁移时可以修改 =my/proxy-address= 的默认值；无需代理时把它设为 =nil=。
这里的 =nil= 清除这份配置设置的显式 URL 代理，不会清除进程已有的代理环境变量。

#+begin_src emacs-lisp
;;; 网络代理
;; 仅影响 Emacs URL 库，不会替 Git、clangd 等外部程序设置代理。
(require 'url-vars)

;; 不需要显式代理时改为 nil；已有的进程代理环境变量不受此设置清除。
(defvar my/proxy-address "127.0.0.1:10808"
  "Local HTTP proxy address, or nil to omit explicit URL proxies.")

;; HTTP/HTTPS 共用本地 HTTP 代理，本机地址绕过代理。
(setq url-proxy-services
      (when my/proxy-address
        `(("http" . ,my/proxy-address)
          ("https" . ,my/proxy-address)
          ("no_proxy" . "\\`\\(localhost\\|127\\.0\\.0\\.1\\|\\[::1\\]\\)\\'"))))
#+end_src

*** 本机特例：MSYS2 GPG 路径兼容修复

这不是 Windows 通用问题，不能仅凭操作系统为 Windows 就强制替换 GPG。
已在当前机器的 Windows Emacs + MSYS2 GPG 组合中复现：
默认 PATH 中的 MSYS2 GPG 无法正确处理 Emacs 传入的 Windows 路径，
会将 =d:/...= 当作相对路径拼接，导致密钥环无法创建，继而报缺少公钥。
Git 自带的 GPG 已实测可处理同一路径。

下面只在默认发现的程序恰好是本机已知的问题路径，并且替代程序存在时启用修复。
其他 Windows、Linux、macOS 保留默认 GPG 选择，不要求安装在 =D:/Software/Git/=。
迁移后若有不同的 GPG 问题，应重新诊断；不要直接照搬本机路径。

使用 =customize-set-variable= 是因为 EasyPG 会检查该变量是否经过自定义；
仅用 =setq= 可能仍然让它从 PATH 自动选择其他 GPG。

#+begin_src emacs-lisp
;;; 本机特例：MSYS2 GPG 路径兼容
;; 仅修复当前已复现问题的可执行文件路径，不是所有 Windows 都需要此设置。
;; 其他 Windows、Linux、macOS 保留默认 GPG 选择；不关闭签名校验。
(require 'epg-config)

(when (eq system-type 'windows-nt)
  (let ((detected (executable-find epg-gpg-program))
        (affected "D:/Software/Msys2/usr/bin/gpg.exe")
        (replacement "D:/Software/Git/usr/bin/gpg.exe"))
    (when (and detected
               (string-equal (downcase detected) (downcase affected))
               (file-executable-p replacement))
      ;; EasyPG 会检查自定义状态；仅 setq 可能仍让它重新从 PATH 选择程序。
      (customize-set-variable 'epg-gpg-program replacement)
      ;; 清除指向旧 GPG 的配置缓存，让后续校验使用替代程序。
      (setq epg--configurations nil))))
#+end_src

*** 通用 GPG 密钥环与软件源初始化

各平台都需要可用的 GPG，并在空密钥环上导入 Emacs 自带的可信 ELPA 公钥。
保留签名校验；本节与上面的本机路径修复分开。

#+begin_src emacs-lisp
;;; 通用签名密钥环与软件源初始化
;; 各平台共用独立的 ELPA 密钥环，不修改个人日常使用的 GPG 密钥环。
(setq package-gnupghome-dir (expand-file-name "gnupg/" package-user-dir))

(require 'epg)

(unless (epg-find-configuration 'OpenPGP)
  (error "GnuPG not found or unusable; install GnuPG and check Emacs exec-path"))

(let ((context (epg-make-context 'OpenPGP)))
  (setf (epg-context-home-directory context) package-gnupghome-dir)
  ;; 初次使用或之前初始化失败留下空密钥环时，导入 Emacs 自带的 ELPA 公钥。
  (unless (epg-list-keys context)
    (package-import-keyring (expand-file-name "package-keyring.gpg" data-directory))))

;; 激活已经安装的插件；此操作本身不更新或升级它们。
(package-initialize)

;; 仅在交互启动且某个源缺少缓存索引时刷新，不在每次启动时联网。
;; 更新索引可用 M-x package-refresh-contents；刷新索引不等于升级插件。
(when (and (not noninteractive)
           (not (seq-every-p
                 (lambda (archive)
                   (file-exists-p
                    (expand-file-name
                     (concat "archives/" (car archive) "/archive-contents")
                     package-user-dir)))
                 package-archives)))
  (package-refresh-contents))
#+end_src

*** use-package

Emacs 29 及以上版本内置 =use-package=，本机 Emacs 31.1 可以直接加载。
如果以后使用较旧版本，才通过 =package.el= 安装它。

=use-package-always-ensure= 让第三方插件默认自动安装；内置功能需要显式写
=:ensure nil=，避免误装 ELPA 上的其他版本。
保留软件包签名校验，不通过关闭校验绕过下载问题。

#+begin_src emacs-lisp
;;; use-package 声明管理
;; Emacs 29+ 使用内置版本；旧版本缺失时才从软件源安装。
(unless (require 'use-package nil t)
  (unless package-archive-contents
    (package-refresh-contents))
  (package-install 'use-package)
  (require 'use-package))

;; 后续第三方插件默认自动安装；内置功能应显式声明 :ensure nil。
(setq use-package-always-ensure t)
#+end_src

声明第三方插件时，之后统一使用这种形式；本段只是示例，不生成配置：

  :defer t)

  :defer t)

*** 自动编号与目录如何配合

这两项是独立功能，不是 toc-org 标签同时控制的：

| 配置                     | 负责内容                                     | 何时更新             |
|--------------------------+----------------------------------------------+----------------------|
| org-num-mode             | 编辑器中显示章节号，不修改标题文本             | 标题增删、移动后更新 |
| TOC_4_org + toc-org-mode  | 在目录章节生成最多四级的 Org 标题链接          | 保存文件前更新       |
| options 中 toc:4 num:4   | 导出文档时生成四级目录与编号                   | 每次导出时生成       |

自动编号根据标题的星号层级和出现顺序计算，例如父标题用 =*=，子标题用 =**=。
将两个同级章节交换位置，org-num 会重新计算它们及其子章节的显示编号；
随后保存文件，toc-org 再按新顺序重建目录。无需手工修改标题中的数字。

不使用全局编号 hook，也不全局设置编号深度。需要编号的 Org 文档，
只需在文件头写下这些元数据；下面是说明示例，不生成 Lisp 配置：

#+begin_example
#+startup: overview num
#+options: toc:4 num:4
#+end_example

- =startup= 中的 =overview=：打开时折叠到顶层概览。
- =startup= 中的 =num=：只为这个文档启用内置的自动编号。
- 不想显示编号时，改为 =#+startup: overview nonum=。
- =options= 中的 =toc:4 num:4=：只控制导出目录和编号到四级，
  不控制编辑缓冲区的编号深度。

修改头部后重新打开文件，或者执行 =M-x org-mode= 重新读取启动选项。
仅想临时开关当前缓冲区的编号，可以执行 =M-x org-num-mode=。
不写 =num= 的其他 Org 文档不会因为本配置而默认开启编号。

编辑器编号采用 Org 默认值：所有层级都可编号，目录标题也可能计入。
如需当前缓冲区最多四级、跳过带 =UNNUMBERED= 属性的目录，可以按需执行
下面的局部设置（=:tangle no=，不会自动启用，也不会影响其他文件）：

#+begin_src emacs-lisp :tangle no
(setq-local org-num-max-level 4
            org-num-skip-unnumbered t)
(org-num-mode -1)
(org-num-mode 1)
#+end_src

Org 没有用 =#+options: num:4= 设置编辑器编号深度的含义，
因此不把导出选项与上述局部设置混为一谈。

*** 自动目录：toc-org

[[https://github.com/snosov1/toc-org][toc-org]] 在保存 Org 文件前，根据实际标题重建目录。
只有含目录标签的文件才会插入目录，不会给所有 Org 文件强加一个目录。
本文件使用 =TOC_4_org= 标签：最多四级标题，生成 Org 原生标题链接，
可用 =C-c C-o= 打开，不依赖 GitHub 风格锚点。
“目录”是标题，=:TOC_4_org:= 是机器识别标签，二者各有用途。

#+begin_src emacs-lisp
;;; Org 自动目录
;; Org 缓冲区启用 toc-org，但只为带 TOC 标签的文档在保存时更新目录。
;; 本配置文档使用 :TOC_4_org:；目前目录只有标题链接，不包含章节编号。
;; 不配置全局 org-num hook；正文编号由每份文件的 #+startup: num 决定。
(use-package toc-org
  :hook (org-mode . toc-org-mode))
#+end_src

插件未安装时由 use-package 自动安装。安装完成后重新打开 Org 文件，
或者先通过 =M-x describe-variable RET toc-org-mode RET= 查看当前状态；
只有未启用时才执行 =M-x toc-org-mode=，避免反而将已启用的模式关闭。
此后新增、删除或重命名标题，保存文件即可更新目录。
也可运行 =M-x toc-org-insert-toc= 立即更新；更新只影响文档目录，不执行代码块。
手动更新方法：打开需要更新目录的 Org 文件，确认已有 TOC 标签，
执行 =M-x toc-org-insert-toc RET=（也可按 =,,,= 后输入该命令），然后保存。
正常情况下 toc-org-mode 已在保存前更新目录，无需每次手动调用。
生成 Lisp 配置是另一件事：在当前 Org 文件里按 =C-c C-v t=，
或运行 =M-x org-babel-tangle RET=；不会自动加载生成结果，也不会要求固定的 Org 文件名。
导出时的自动目录仍由 =#+options: toc:4= 独立控制，和本文内的目录用途不同。

*** 标题跳转：org-goto

=org-goto= 是主动调用的 Org 标题导航命令，不是根据光标自动跳转的后台功能。
执行 =C-c C-j= 或 =M-x org-goto= 使用 Org 默认的大纲定位界面。
前面的说明示例展示了可选的 =outline-path-completion= 界面，当前并未启用；
需要时可用它选择标题路径后跳转，再配合 Vertico / Orderless 改善候选界面。
这两种方式都读取当前文档标题，无需维护目录。

*** 标题与符号索引：Imenu

Imenu 是 Emacs 内置的“当前缓冲区结构索引”，不是另一个目录插件。
在 Org 中列标题，在编程模式中通常列函数、类型等符号，内容由当前模式提供。
执行 =M-x imenu=，选择索引项并跳转，不会在文件中插入或更新文字。
第二阶段通过 =, o i= 或 =, s i=（=M-x consult-imenu RET=）提供带预览的选择界面。

| 需要做的事                   | 使用功能                 |
|------------------------------+--------------------------|
| 文档里有一份自动更新的目录   | toc-org，保存时更新       |
| 按标题路径定位 Org 章节      | org-goto，选择后跳转      |
| 查找当前文件的标题／代码符号 | imenu 或 consult-imenu    |

**** evil-surround 的包围符操作

先记语法，而不是背组合表：添加用 =ys + 范围 + 新包围符=；
删除用 =ds + 旧包围符=；替换用 =cs + 旧包围符 + 新包围符=。
只有添加需要 motion/text object 来选择范围；删除、替换根据旧包围符定位内容，
不要套成 =ds + motion= 或 =cs + motion=。

添加通过 Evil 的 operator-range 取得范围，所以可以组合大多数可用于操作符的
motion、计数和文本对象；不是所有普通模式按键都能用，比如切窗、保存不是范围动作。
范围的 inclusive/exclusive、跨行、块选择行为仍服从 Evil，不能保证任意扩展 motion 都兼容。

| 添加范围 | 含义 | 完整例子 |
|----------+------+----------|
| iw / aw | 当前单词内部／含周围空白 | ysiw" / ysaw" |
| iW / aW | 空白分隔的大 WORD | ysiW" / ysaW" |
| e / 2e | 从光标到单词尾／第二个单词尾 | yse" / ys2e" |
| w / b | 向前／向后单词 motion | ysw" / ysb" |
| $ / 0 | 到行尾／行首 | ys$" / ys0" |
| f, / t, | 到逗号／逗号前 | ysf," / yst," |
| i( / a( | 括号内部／含原括号 | ysi(] / ysa(] |
| i" / a" | 引号内部／含原引号 | ysi"' / ysa"' |
| ip / ap | 段落内部／含段落边界 | ysip} / ysap} |

这个表覆盖语法类别，不是 motion 的穷举：你已会的范围动作通常可以代入，
前提是能在 Evil 操作符后产生有效范围。注意 =ysw= 在该插件中有类似 change 操作的
单词边界处理，不要把所有 motion 的边界都理解成简单字符位移。

操作形态还包括：=yss + 包围符= 包当前行；=ys + 计数 + s + 包围符= 包多行；
=yS + 范围 + 包围符= 添加带换行的包围；=ySS + 包围符= 是行形式。
可视模式先选择字符、行或块，再按 =S + 包围符=；=gS + 包围符= 切换换行包围行为。
删除和替换分别如 =ds)=、=ds"=、=cs)]=、=cs"'=；=dst=、=cst + 新包围符=
用于已有标签。添加一行／多行及可视选择会根据范围类型进行缩进和换行。

本机 evil-surround 1.0.4 的默认新包围符如下（可通过 evil-surround-pairs-alist 扩展）：

| 触发字符 | 生成方式 |
|----------+----------|
| ) / ] / } | 紧贴内容的圆／方／花括号 |
| ( / [ / { | 括号内侧各有一个空格 |
| b / B | 分别为紧贴内容的圆／花括号别名 |
| > | 尖括号 |
| # | 左边为 #{，右边为 } |
| t / < | 继续输入 HTML/XML 标签，例如 ysiwt 后输入 em 并确认 |
| f | 继续输入函数名，生成函数调用，例如 ysiwf 后输入 print 并确认 |
| 双引号、单引号、反引号等 | 默认两边插入同一字符 |
| a / w 等未列入配对表的普通字符 | 同样两边插入该字符，不表示 motion |

因此 =ysiw= 还没输入完：iw 是范围，后面仍需包围符。
=ysea= 已经完整：ys + e + a，在范围两边插入 a。
=ysew= 同样完整：ys + e + w，在范围两边插入 w。
二者没有“不行”，只是结果不是引号或括号；=ysiw"= 也完全没有特殊待遇。
例如光标在 hello 的第一个字母，yse" 得到 "hello"，ysea 得到 ahelloa，ysew 得到 whellow。
标签／函数触发需要额外输入，Esc 可取消，u 撤销；原生 ds/cs 使用已有文本对象定位，
新包围符表不意味着任意自定义字符都能自动作为旧包围符被识别。

evil-surround 模仿 Vim 的 surround.vim，核心是“添加／删除／替换操作 + 动作或文本对象 + 包围符”。
它的按键不是 leader 命令；先按操作前缀，Evil 进入等待动作的 operator-pending 状态，
再按 motion 或 text object，最后输入分隔符。

拆开 =ysiw"= 看：

| 片段 | 含义 |
|------+------|
| =ys= | surround operator，开始给目标添加包围符 |
| =i=  | inner，选择“内部”文本对象，不包含外层空白或包围符 |
| =w=  | word，当前单词文本对象 |
| ="=  | 输入要添加的包围符，这里是双引号 |

所以 =ysiw"= 的完整意思是“给当前单词加双引号”。
这里的 =i= 不是插入模式；它是文本对象前缀。=a= 表示 around，通常包含对象周围的空白或包围符。

例子 =yse)= 拆成：

- =ys=：开始添加包围符。
- =e=：motion，移动到当前单词结尾。
- =)=：选择圆括号这一组包围符，evil-surround 会补上对应左括号。

因此，光标在单词开头时，=yse)= 会用圆括号包住从光标到该单词结尾的范围。
若要对整个单词操作，不依赖光标刚好位于开头，使用文本对象更明确：=ysiw"= 添加双引号，
=ysaw)= 添加圆括号。最后的字符是要使用的包围符；左右成对的符号均可作为触发字符。

你问的 =ysew= 也可以被解析，但不是“end word”的组合：=e= 已经完成范围选择，
后面的 =w= 会被当作包围字符。本机默认包围符表没有 w 的特殊配对，
因此它会在两侧各插入字母 w，例如光标在 hello 开头时得到 whellow。
要用双引号包到单词结尾，应输入 =yse"=；要包两个词，可用 =ys2e"=。

=ds"= 拆成 =d=（delete）+ =s=（surround）+ ="=（已有双引号），
只删除引号并保留内容；=cs"'= 是 =c=（change）+ =s= + 旧双引号 + 新单引号。
=ys= 沿用 surround.vim 的习惯，用 y 操作符接 s 启动添加操作，并非把文字复制后粘贴。
括号触发也有区别：右括号 =)= 通常添加紧贴内容的括号，左括号 =(= 会在内侧加空格。

常见操作如下：

| 目标                         | 按键示例                     |
|------------------------------+------------------------------|
| 给当前单词加双引号           | =ysiw"=                      |
| 给当前单词（含 around 范围）加双引号 | =ysaw"=                |
| 从光标包到当前单词结尾，用括号包围 | =yse)=                   |
| 给当前单词加圆括号             | =ysiw)=                       |
| 删除现有双引号               | =ds"=                        |
| 将双引号改成单引号           | =cs"'=                       |
| 包围可视选择                 | 先 =v= 选择，再 =S=，输入包围符 |
| 用换行包围可视选择           | 先 =v= 选择，再 =gS=           |

建议先在临时文件中体验，必要时用 =u= 撤销；句点 =.= 保留重复编辑功能。
文本对象还包括 =i(=（括号内部）、=a(=（含括号）、=i"=（引号内部）、=ip=（段落内部）。
可用 =, h f= 查询 =evil-inner-word=、=evil-a-word= 等函数说明，
或者 =, h k= 查询当前操作键。不要把 =ys=、=ds=、=cs= 和 leader 菜单混在一起记。

**** 屏幕内定位：Avy

[[https://github.com/abo-abo/avy][Avy]] 提供类似 Flash.nvim 的“输入字符 → 显示标签 → 按标签跳转”操作。
它们的功能并非逐项对应。本配置的默认范围是当前窗口中可见的文字，
不是整个缓冲区：缓冲区包括滚动后才看得见的内容，同一缓冲区也可以显示在多个窗口中。
折叠或尚未显示的内容不要依赖 Avy 查找，改用 =, s s=（=M-x consult-line RET=）。

#+begin_src emacs-lisp
;;; 屏幕内定位：按命令加载，不在启动时扫描缓冲区。
(use-package avy
  ;; 为这两个命令建立自动加载入口；首次调用才加载 Avy，不是在这里设置快捷键。
  :commands (avy-goto-char-timer avy-goto-line)
  :custom
  ;; 本配置选择 nil：当前窗口；插件默认 t：当前 Frame 全部窗口；all-frames：全部 Frame。
  (avy-all-windows nil)
  ;; 默认 0.5 秒：连续字符输入停顿多久后显示标签；可改为 0.8 或 1.0，给输入更多时间。
  (avy-timeout-seconds 1.0)
  ;; 默认 t：RET 提前结束文字输入并显示标签；nil 则把 RET 当作换行字符匹配。
  (avy-enter-times-out t)
  ;; 默认 t：匹配文字忽略大小写；改为 nil 后区分大小写。
  (avy-case-fold-search t)
  ;; 默认标签键：?a 表示字符 a；可调整字符及顺序，不是要查找的目标文字。
  (avy-keys '(?a ?o ?e ?u ?i ?d ?h ?t ?n)))
#+end_src

这里修改跳转范围，并把常用参数按本机 Avy 0.5.0 默认值显式写出，便于后续修改。
=avy-timeout-seconds= 当前为 0.5 秒，可在上面的 :custom 中改为 0.8 或 1.0。
该时间是连续输入字符的等待时间，不是看到标签后必须立即完成选择的时间限制。
其他交互命令由包的自动加载定义提供，使用 M-x 即可；无需为每个命令增加按键。

***** 字符跳转：先输入文字，再选择标签

1. 在普通模式按 =s=，或 =, j j=；也可执行 =M-x avy-goto-char-timer RET=。
2. 输入屏幕上目标文字中的一个或连续多个字符，例如 =config=。
   相邻输入间隔超过默认 0.5 秒后，Avy 开始选择；默认也可用 RET 提前结束文字输入。
3. 多个目标出现标签后，输入目标旁的标签字符。标签可能不止一个字符，按显示的顺序输入。
   标签是临时选择键，与刚才输入的目标文字是两个步骤。
4. 唯一候选通常直接跳转；没有候选时不会跳到任意位置。
   需要放弃时按 =C-g=，重新调用后可换用更短的文字或先滚动到目标附近。

例如当前窗口有多个 =use-package=，输入 =use= 后按其中一个位置的标签；
如果想精确定位 =use-package avy=，可以输入更有区分度的连续片段。
不要把 Orderless 的空格分词套到这里：Avy 的计时字符跳转查找连续文字。
普通模式原来的 =s= 替换字符操作改用 =cl=；插入模式的 s 仍输入普通字母。
Avy 跳转后可用 =M-x avy-pop-mark RET= 返回它记录的前一位置。

***** 行跳转、单词跳转与范围选择

=, j l= 或 =M-x avy-goto-line RET= 为可见行显示标签，不需要先输入行内文字。
例如目标是一整行注释，直接选择该行的标签比输入共同出现的注释前缀更方便。

下表命令均可通过 =M-x 命令名 RET= 调用；没有列出快捷键的命令本轮不额外绑定。

| 命令 | 输入与用途 |
|------+------------|
| avy-goto-char | 读取一个字符，在可见的该字符位置选择 |
| avy-goto-char-2 | 依次读取两个字符，适合固定两字符定位，不等待计时结束 |
| avy-goto-char-in-line | 在当前行的可见部分选择一个字符 |
| avy-goto-char-2-above / avy-goto-char-2-below | 限定光标上方／下方的可见范围，使用两字符定位 |
| avy-goto-word-0 | 直接为可见单词起始位置提供选择，不先输入字符 |
| avy-goto-word-1 | 输入一个字符，只选择以该字符开头的单词 |
| avy-goto-word-0-above / avy-goto-word-0-below | 限定上方／下方的单词起始位置 |
| avy-goto-word-1-above / avy-goto-word-1-below | 限定上方／下方，输入单词首字符后选择 |
| avy-goto-line | 选择可见行 |
| avy-pop-mark | 返回 Avy 保存的跳转位置 |

单词边界受当前模式的语法规则影响，不等于按中文语义分词。
支持前缀参数的字符／单词命令可临时反转窗口范围，例如
=C-u M-x avy-goto-char-timer RET= 本次允许选择当前 Frame 的其他窗口；
不修改 =avy-all-windows= 的持久设置。各命令的前缀参数含义并不完全相同，
特别是行编辑命令可能把数值参数当作行数，先用 =C-h f= 查询对应说明。

***** 复制、移动与删除：按标签选择操作对象

Avy 还可以选择远处的行或范围后编辑。以下命令会涉及文字变更，
应先在临时文件中试用；它们不是单纯的光标跳转，也不自动保存文件。

| M-x 命令 | 效果 |
|----------+------|
| avy-copy-line | 选择一行，复制到当前行上方；数值前缀可指定行数 |
| avy-move-line | 选择一行，移动到当前行上方；原位置文字随之移除 |
| avy-copy-region | 选择两行，将其间的文本复制到当前行附近，默认插在当前行上方 |
| avy-move-region | 选择两行，将其间文本移动到当前行上方 |
| avy-kill-whole-line | 选择并剪切整行，保存到 kill ring |
| avy-kill-ring-save-whole-line | 选择整行复制到 kill ring，不删除 |
| avy-kill-region | 选择两行并剪切其间范围 |
| avy-kill-ring-save-region | 选择两行并将其间范围复制到 kill ring |

例如先把光标放在需要插入内容的行，执行 =M-x avy-copy-line RET=，
再按源行标签，源行副本会出现在当前行上方。范围命令按两次选择确定范围，
执行前先查看 =C-h f= 的边界说明，避免把行范围误认为任意字符范围。
Avy 也支持标签阶段的 action dispatch，具体键和动作由 =avy-dispatch-alist= 决定。
本配置不修改该表；查阅 =C-h v avy-dispatch-alist= 后再使用，
不要把 action 函数名当作独立的 M-x 命令。更完整的可用命令可在 M-x 输入 =avy-= 查询。

**** 搜索与选择：Vertico / Orderless / Marginalia / Consult

这四个插件各自负责一层功能：

| 插件 | 职责 | 在哪里能看到效果 |
|------+------+------------------|
| Vertico | 显示纵向候选列表 | M-x、find-file 和采用标准补全接口的命令 |
| Orderless | 决定输入如何匹配候选 | 多个空格分隔关键词逐步缩小列表 |
| Marginalia | 为支持的候选类别附加说明 | 命令说明、文件属性等注释 |
| Consult | 提供搜索、切换与导航命令 | consult-line、consult-buffer 等带预览的选择 |

它们不提供代码缓冲区内的弹出补全；后续 Corfu 负责那个界面。
本阶段不改 =completion-in-region-function=，也不引入 Embark 等额外插件。

***** Vertico：候选列表与确认方式

[[https://github.com/minad/vertico][Vertico]] 接管标准 minibuffer 补全的候选显示。
minibuffer 是 Emacs 底部读取命令和参数的输入区域，不是新的文件缓冲区。
开启后，原来的 =M-x=、=,,,=、=, f f=（=M-x find-file RET=）仍是相同命令入口。

#+begin_src emacs-lisp
;;; 候选界面：默认候选数量，按内容动态增减高度，不首尾循环。
(use-package vertico
  :custom
  (vertico-count 10)   ; 默认 10：最多显示的候选数；可改为 15 或 20，受窗口高度限制。
  (vertico-resize t)   ; 按已选行为动态增减高度；nil 固定高度，grow-only 只增高不缩小。
  (vertico-cycle nil)  ; 默认 nil：首尾不循环；改为 t 后从末尾继续向下会回到开头。
  :init
  (vertico-mode 1))    ; 启动时启用全局候选界面；1 是启用，不是候选数量。
#+end_src

将本机 Vertico 2.15 的默认 =vertico-count=（10）显式写出，方便以后调整数量上限。
=vertico-resize=t= 允许高度随候选增减；实际可见高度仍受 minibuffer 窗口限制。
=vertico-cycle=nil= 表示到达首尾时不绕回另一端，避免连续移动时突然选到相反位置。
这些是显示行为，不决定搜索整个文件还是当前窗口。

| 默认按键 | 作用 |
|----------+------|
| C-n / C-p、下／上方向键 | 选择下一个／上一个候选 |
| RET | 确认当前候选 |
| TAB | 将选中候选填入输入区，便于继续修改，不等于最终确认 |
| M-RET | 提交输入区原始文字，不强制采用高亮候选 |
| C-g | 取消当前输入 |

例如用 =, f f= 输入目录和文件名，选中已有文件后 RET 打开。
若输入一个尚不存在的新文件名，而列表仍高亮已有文件，使用 =M-RET= 提交自己的名字；
也可上移到输入提示行后 RET。创建文件缓冲区后仍需显式保存才会写入磁盘。
M-RET 不是绕过命令自身的校验：必须从候选选择的命令仍可能拒绝不存在的对象。
minibuffer 中沿用 Emacs 输入键；不要把普通模式 hjkl 当作候选移动键。

***** Orderless：多关键词如何匹配

[[https://github.com/oantolin/orderless][Orderless]] 改善候选筛选。Vertico 展示结果，Orderless 决定哪些候选留下。

#+begin_src emacs-lisp
;;; 匹配规则：普通候选使用 Orderless，文件保留基础和部分路径补全。
(use-package orderless
  :demand t  ; 启动时加载匹配样式，确保第一次打开候选界面时已经可用。
  :custom
  ;; 本配置的普通补全顺序：先多关键词匹配，再尝试 basic；不是 Emacs 原始默认值。
  (completion-styles '(orderless basic))
  ;; 清除类别自带的默认样式，避免覆盖上面的统一规则；nil 不是关闭补全。
  (completion-category-defaults nil)
  ;; 文件类别单独处理：basic 优先兼容路径／TRAMP，partial-completion 支持部分路径。
  (completion-category-overrides '((file (styles basic partial-completion))))
  ;; Orderless 1.8 默认：每个关键词可按字面或正则匹配；只保留 orderless-literal 可禁用正则。
  (orderless-matching-styles '(orderless-literal orderless-regexp)))
#+end_src

默认用空格分隔多个匹配部分，各部分都要命中，但出现顺序不限。
例如在 =M-x= 输入 =buffer switch=，再改为 =switch buffer=，都可筛选名称含这两部分的命令。
可以先输入较宽泛的 =buffer=，再加 =switch= 缩小范围，而不必记住完整命令名。
这不是自动纠正拼写，也不是默认任意字符模糊匹配：默认匹配方式包含字面与正则匹配，
例如 =^consult-= 可匹配以 consult- 开头的候选，点号等字符也可能有正则含义。
不需要正则时先用普通文字；不匹配时删掉复杂表达式，再逐步增加关键词。

=basic= 作为普通候选的后备样式，兼容依赖动态补全表的命令。
=completion-category-defaults=nil= 去掉类别默认样式，由这里的规则明确选择匹配方式；
=completion-category-overrides= 为文件类别单独选择 basic 和 partial-completion，
basic 优先也有助于 TRAMP 主机名补全。文件输入因此不承诺与命令候选相同的空格分词行为。
partial-completion 提供部分路径和通配符补全；路径效果还取决于系统和 Emacs 版本。
Windows 可以使用 =D:/目录/文件= 这样的路径，空格也可能是实际文件名的一部分。
本阶段不添加自定义匹配分派器、额外前缀语法或 Emacs 31 专属匹配设置。

***** Marginalia：候选旁边的信息

[[https://github.com/minad/marginalia][Marginalia]] 为支持的补全类别添加注释；注释不是候选名称的一部分。

#+begin_src emacs-lisp
;;; 候选注释：使用内置注释器，不增加自定义类别或切换键。
(use-package marginalia
  :custom
  (marginalia-align 'left)   ; 默认 left：注释左对齐；也可选 center 或 right。
  (marginalia-align-offset 0) ; 默认 0：注释对齐的额外偏移列数；增大可增加间距。
  :init
  (marginalia-mode 1))      ; 启动时启用候选注释；不需要每个缓冲区分别开启。
#+end_src

例如 M-x 中可看到命令的说明或按键，文件选择中可看到文件属性，
变量和函数候选也可能显示类型或文档摘要。实际字段取决于类别和安装版本。
普通命令已有自己的注释时，显示结果也受原有补全元数据影响；并非每个候选都有附加信息。
这些注释用于辅助选择，不代替 =C-h f=、=C-h v= 等完整帮助。

执行 =M-x marginalia-cycle RET= 可以切换注释器，再打开原来的候选界面观察区别。
本轮保留默认注释器，不给切换操作单独绑定按键；多数时候无需反复调整。
插件会用于后续候选界面，不需要在每个文件中手动启动。

***** Consult：已绑定的搜索与导航

[[https://github.com/minad/consult][Consult]] 提供实际命令，通过标准候选界面展示结果，并支持预览。

#+begin_src emacs-lisp
;;; 搜索与选择命令：首次调用时加载，保留插件默认预览策略。
(use-package consult
  ;; :commands 声明自动加载入口，不执行这些命令，也不定义快捷键。
  ;; 四个命令分别负责缓冲区选择、当前缓冲区搜索、外部 rg 搜索、结构索引。
  ;; 首次调用其中任意一个才加载插件；启动时不必加载整套搜索实现。
  :commands (consult-buffer consult-line consult-ripgrep consult-imenu)
  :custom
  ;; 默认 any：选中候选变化时自动预览；nil 关闭预览，"M-." 改为按该键手动预览。
  (consult-preview-key 'any)
  ;; 默认 3 个字符才启动异步外部搜索；可改为 2，小值更早搜索但更容易产生大量结果。
  ;; 仅影响 consult-ripgrep 等异步命令，不限制 consult-line 的本地筛选。
  (consult-async-min-input 3))
#+end_src

上述声明为本配置绑定的命令建立加载入口；其他官方交互命令使用包提供的自动加载。
这里的 :commands 是 use-package 的加载声明，不是“只允许使用这四个命令”的白名单。
列出它们是为了确保统一键位引用的主要命令可以按需加载；其他交互命令仍可通过 M-x 使用。
修改按键应去最后的统一快捷键章节，修改预览或搜索阈值则改这里的 :custom。
不把 Consult 的内部函数作为配置接口；预览和搜索阈值显式保留本机 Consult 3.10 默认值。
通常移动候选即可看到预览，RET 确认，C-g 取消并返回调用前的位置或显示。
预览不等于保存文件；不同命令的预览内容可能是缓冲区、位置或插入文字。
预览文件也可能触发访问文件的正常行为；远程文件等来源可能限制预览。

| 快捷键 | M-x 命令 | 选择对象 |
|--------+----------+----------|
| , b b | consult-buffer | 缓冲区及当前启用的其他来源 |
| , s s | consult-line | 当前缓冲区的匹配行 |
| , s r | consult-ripgrep | 项目或目录中的磁盘文件匹配 |
| , s i / , o i | consult-imenu | 当前缓冲区的结构索引 |

=, b b=：输入缓冲区名称片段，C-n / C-p 移动时预览，RET 切换，C-g 取消。
它替换原键位的 switch-to-buffer，但 =M-x switch-to-buffer RET= 仍可直接使用。
Consult 的默认来源还可以包含书签、最近文件等；本阶段没有启用 recentf，
因此不保证出现最近文件候选，不把安装 Consult 等同于建立最近文件记录。
默认可用 =b SPC= 缩小到缓冲区来源，退格删除筛选输入后恢复选择；
其他来源是否出现取决于实际启用的功能。

=, s s=：在当前缓冲区输入文字，例如 =use-package=，选择匹配行跳转。
它能搜索屏幕外的内容；若缓冲区被 narrow，则只搜索当前可访问范围。
可输入多个 Orderless 关键词筛选行。按 =M-n= 可访问命令提供的未来历史，
例如光标处符号；没有合适内容时直接自行输入。预览后 C-g 可放弃跳转。

=, s i= 或 =, o i=：选择 Imenu 结构项，例如 Lisp 函数、Org 标题。
项目由当前主模式的 Imenu 支持决定，不是语言服务器的跨文件符号搜索；
空列表可能表示模式没有提供索引，不能据此认为文件没有任何结构。
原生 =M-x imenu RET= 仍可使用，不全局设置索引层级。

***** ripgrep：项目搜索与外部程序

=, s r= 或 =M-x consult-ripgrep RET= 启动异步文本搜索。
默认使用 Emacs 识别到的项目根目录；无项目时使用当前 default-directory，
提示区会显示搜索目录。=C-u M-x consult-ripgrep RET= 可先选择目录。
项目识别采用现有内置机制，本阶段不增加 project.el 管理配置。

1. 先在 Emacs 执行 =M-: (executable-find "rg") RET=。结果为 nil 表示 Emacs 找不到 rg。
   shell 中能够运行 rg 不代表图形 Emacs 一定继承相同 PATH。
2. 打开本仓库的文件，按 =, s r=，检查目录，再输入 =use-package= 等搜索词。
3. 输入达到 Consult 的异步搜索最小长度后才开始执行外部搜索；结果到达可能有短暂延迟。
4. 移动候选预览位置，RET 打开目标；C-g 取消。

Consult 的外部搜索支持 =#搜索表达式#候选过滤= 形式，例如
=#use-package#evil=：前半部分交给外部搜索，后半部分继续筛选返回的候选。
不要把输入区所有空格都当作普通文件名搜索；具体正则转换和选项见官方说明。
默认 rg 规则通常遵守忽略文件，不默认搜索所有隐藏或被忽略文件。
搜索磁盘文件不会包含尚未保存的缓冲区修改；查找这类内容用 consult-line。
没有结果时先检查目录、搜索长度、忽略规则和磁盘保存状态，再判断是否插件故障。
本配置不安装 rg、不修改系统 PATH，也不硬编码 Codex 内部工具路径。

***** 其他 Consult 命令：通过 M-x 使用

以下功能本轮不增加快捷键。已绑定入口覆盖日常搜索和切换，
这些功能先按场景通过 M-x 使用，避免一次增加大量难以记忆的键位；
后续根据实际频率再安排按键。未绑定不等于禁用，也不需要为每次调用重新配置。

| M-x 命令 | 前提与使用过程 |
|----------+----------------|
| consult-yank-pop | kill ring 中已有复制／剪切内容；选择并预览文字后 RET 插入，紧接 yank 后可能替换上一次粘贴 |
| consult-mark | 当前缓冲区 mark-ring 已有记录；选择位置预览，RET 跳转 |
| consult-global-mark | global-mark-ring 已有跨缓冲区记录；选择记录后跳转到对应缓冲区与位置 |
| consult-outline | 当前模式提供 outline 标题规则；选择标题，预览后 RET 跳转 |
| consult-history | 在支持的输入上下文中选择历史，例如 shell 的命令历史或 minibuffer 输入历史 |
| consult-bookmark | 已有书签时选择书签并跳转；可用内置 bookmark-set 先建立书签 |
| consult-goto-line | 输入行号，或 line:column，预览后 RET 确认 |
| consult-line-multi | 搜索多个缓冲区；默认项目缓冲区，前缀参数可扩大到全部缓冲区 |
| consult-imenu-multi | 选择项目中相同主模式的缓冲区索引项，需要相应缓冲区已打开并提供 Imenu |

例如先在临时文件复制两段文字，再执行 =M-x consult-yank-pop RET=，
选择旧的一段，观察预览后 RET 插入；C-g 取消。Evil 的寄存器语义与 Emacs kill ring
并非完全相同，候选以实际 kill ring 内容为准。该命令会修改文本，不自动保存。

标记历史也不是所有光标移动的完整录像。可先用 =C-SPC C-SPC= 在当前位置设置并取消激活标记，
移动到另一个位置再次设置标记，然后执行 =M-x consult-mark RET= 查看已有记录。
跨文件历史用 consult-global-mark，但只会出现 Emacs 实际记入全局标记环的位置。
没有记录时应先建立记录，不需要重装插件。

在 Org 中可执行 =M-x consult-outline RET= 选择标题，与 consult-imenu 对比；
两者分别依赖 outline 与 Imenu 规则，不保证每个主模式给出相同候选。
书签可在文件位置用 =M-x bookmark-set RET= 命名建立，再通过
=M-x consult-bookmark RET= 选择；书签持久化沿用 Emacs 自身机制，本轮不改保存策略。

consult-history 读取调用上下文的历史。在已经使用的 =M-x shell RET= 缓冲区中，
有命令历史后执行 =M-x consult-history RET=，选择记录并 RET 填回输入行，
再决定是否执行；普通文本缓冲区不一定提供可用历史，不能当作全局历史浏览器。
在 minibuffer 中直接调用该命令可读取当前输入历史，但本配置没有为它设置局部键位，
也不全局开启递归 minibuffer；不要在 find-file 输入区再次按 M-x 来试图嵌套调用。
该场景本阶段用原生 =M-p / M-n= 浏览历史；consult-history 的 minibuffer 专用入口留待需要时配置。
savehist 尚未启用，不能保证重启后仍保留本次输入历史。

** 帮助与交互提示

*** 帮助查询

Helpful 增强按键、函数和变量帮助，=describe-mode= 查看当前模式说明；
Consult 主要负责搜索和选择，不是帮助文档增强包。
帮助入口覆盖：按键解释、命令／函数说明、变量说明、光标处符号帮助、
当前模式帮助、当前有效键位列表、根据命令查找按键、Emacs 手册和本 Org 配置。

#+begin_src emacs-lisp
;;; 帮助增强：调用时加载 Helpful，安装由 use-package 处理。
;; 实际按键在末尾统一绑定，不在这里覆盖任何模式键位。
(use-package helpful
  :commands (helpful-key helpful-callable helpful-command
             helpful-variable helpful-at-point))
#+end_src

使用方法：=, h k= 后再按想查询的键，例如 =.=，即可查看它的命令与说明。
=, h m= 查看当前模式怎么操作，=, h b= 列出当前有效按键，
=, h w= 根据命令查找已有快捷键。忘记命令名时仍可用 =M-x= 搜索。
Helpful 中的“光标处符号”主要指 Emacs Lisp 符号，不代替未来 clangd 的代码文档。
帮助界面使用 evil-collection 适配；常见 =q= 返回，=TAB= 选择链接，回车打开。

*** 按键提示：which-key

which-key 归为交互提示，和帮助文档查询分开：它负责显示当前前缀后可用的按键。
Emacs 31.1 内置，使用 =:ensure nil=，不下载另一个版本。
本节配置启用方式和提示延时；具体分组名、命令描述放到最后的键位章节。
输入前缀后等待即可提示；没有自定义绑定的命令仍可从 =M-x= 搜索执行。

#+begin_src emacs-lisp
;;; 前缀按键提示：输入 leader 后稍等，显示下一步可用命令。
(use-package which-key
  :ensure nil
  :demand t
  :custom
  (which-key-idle-delay 0.5)
  :config
  (which-key-mode 1))
#+end_src

例如普通模式输入 =,= 后等半秒，会显示文件、缓冲区、帮助等分组。
接着按 =h= 可看到帮助子菜单，按 =C-g= 取消未完成的按键序列。
它只提示你已经按下前缀后可用的键，不会给每个普通输入字符弹出说明。

** 窗口与缓冲区

状态：已配置，等待手动启动验证。Window 指 Emacs 内部分割区域，
Buffer 是打开的内容，Frame 是操作系统中的 Emacs 窗口。关闭 Window 不会删除 Buffer。
窗口放在 w（Window）分组，退出放在 q（Quit）分组；正式按键定义集中在最后。
方向切换仍兼容 Evil 的 =C-w h/j/k/l=，这里额外提供带提示的 leader 入口。
关闭当前窗口用 =, w c=，c 取 Close，调用 Emacs 内置 delete-window；
最后一个普通窗口无法用此命令关闭，应使用明确的退出操作。
方向切换统一使用 =, w h/j/k/l=，与原生 Evil 的 =C-w h/j/k/l= 对应。
左右并排是 vertical split，上下堆叠是 horizontal split。

*** Winner 布局历史与最大化恢复

Winner 是 Emacs 内置的窗口布局历史，不需要安装第三方包。
=, w m= 第一次只显示当前窗口，再按一次恢复这次最大化前的布局；
恢复的是窗口与缓冲区布局，不是撤销文件内容。
最大化期间如果关闭了帧、删除了缓冲区或修改布局，恢复可能无法完全还原。
其他布局操作仍可通过 =M-x winner-undo= / =winner-redo= 查询和恢复。

#+begin_src emacs-lisp
;;; Window configuration history：内置 Winner 记录布局历史；最大化切换另存 Frame 布局。
(use-package winner
  :ensure nil
  :demand t
  :config
  (winner-mode 1))
#+end_src

*** 退出行为

=, q q= 使用 evil-quit：多窗口时关闭当前窗口，只有一个窗口时尝试关闭 Frame，
最后可能退出 Emacs；server/client 场景行为不同，保留 Evil 默认处理。
=, q a= 使用 save-buffers-kill-terminal，按 Emacs 的退出流程检查未保存内容；
在 daemon 或多终端场景不一定停止整个后台进程。
=, q Q= 按你的选择提供 kill-emacs，直接退出进程，不走逐文件保存询问；
可能丢失所有未保存修改，也会结束后台会话，大小写 Q 用于与常规退出区分。
这三个入口都不在配置生成时执行，只在你按对应键时调用。

** 诊断与配置状态

查看启动消息、错误和配置状态不属于 Org 操作，独立归到诊断分组。
d 表示 Diagnostics（诊断），范围比 Debug（调试）更广。
保留 =, d m=（Messages，查看消息）和 =, d d=（Debug，切换错误回溯）。
不增加行号、变量、函数、按键查询的额外诊断入口，后续按实际工具需要再安排。
可用的帮助查询仍保留在 h（Help）分组。候选讨论与审核放在对话里，不写入配置文档。

** 统一快捷键配置（最后配置）

这里集中定义前面所有功能的自定义快捷键，包括 leader、Avy 直达键、
帮助入口和模式专用绑定。功能章节负责“做什么、如何启用”，本节负责“按什么键”。
即使某个模式需要延迟绑定，也在本节使用 =with-eval-after-load= 等机制处理，
不因为需要等它加载就把键位散回功能章节。

*** 管理方式：General

建议采用 [[https://github.com/noctuid/general.el][general.el]]。它不是必须插件，内置键位 API 与 Evil 也能完成绑定；
但本配置涉及多个 Evil 状态、逗号 leader、前缀分组和提示名称，General 能统一这些声明。
它负责定义键位，Evil 提供编辑状态，which-key 展示可用键位，Helpful 解释命令。
General 不会自动启用 which-key，也不代替插件本身。

状态：已配置，等待手动启动安装和验证。
下面创建一份共享 leader keymap，再同时绑定到逗号与备用前缀，避免维护两套菜单。
先定义子 keymap，再组合分组；对 Helpful 的引用由前面的 =:commands= 提供自动加载。

#+begin_src emacs-lisp
;;; 窗口布局与文件辅助命令；Org 生成和目录更新直接使用原生命令。
;; Window maximize：布局保存在当前 Frame 参数中，各 Frame 互不干扰。
(defun my/toggle-window-maximize ()
  "Toggle between the current window layout and a single window."
  (interactive)
  (let ((saved (frame-parameter nil 'my/window-configuration)))
    (if (window-configuration-p saved)
        (progn
          (set-window-configuration saved)
          (set-frame-parameter nil 'my/window-configuration nil))
      (unless (one-window-p)
        (let ((configuration (current-window-configuration)))
          (delete-other-windows)
          (set-frame-parameter nil 'my/window-configuration configuration))))))

;; 只复制当前文件的绝对路径，不修改文件；无文件的缓冲区会明确提示。
(defun my/copy-file-path ()
  "Copy the current file's absolute path to the kill ring."
  (interactive)
  (unless buffer-file-name
    (user-error "Current buffer is not visiting a file"))
  (let ((path (expand-file-name buffer-file-name)))
    (kill-new path)
    (message "Copied: %s" path)))

;;; 统一键位：General 管理绑定，which-key 显示随 keymap 保存的中文描述。
(use-package general
  :after evil
  :demand t
  :config
  (defvar my/leader-map (make-sparse-keymap))
  (defvar my/command-map (make-sparse-keymap))
  (defvar my/file-map (make-sparse-keymap))
  (defvar my/buffer-map (make-sparse-keymap))
  (defvar my/help-map (make-sparse-keymap))
  (defvar my/diagnostic-map (make-sparse-keymap))
  (defvar my/window-map (make-sparse-keymap))
  (defvar my/quit-map (make-sparse-keymap))
  (defvar my/org-map (make-sparse-keymap))
  (defvar my/jump-map (make-sparse-keymap))
  (defvar my/search-map (make-sparse-keymap))

  (general-def my/file-map
    "f" '("打开文件" . find-file)                   ; Find file，打开文件
    "s" '("保存文件" . save-buffer)                 ; Save，保存
    "a" '("另存为" . write-file)                    ; Save as，另存为
    "d" '("目录管理" . dired)                       ; Dired，目录管理
    ;; 保留内置确认：不要用无提示覆盖方式重新读取有未保存修改的文件。
    "u" '("重新读取文件" . revert-buffer)           ; Update from disk，重新读取磁盘内容
    "p" '("复制文件完整路径" . my/copy-file-path))  ; Path，文件完整路径

  (general-def my/buffer-map
    "b" '("切换与预览缓冲区" . consult-buffer)     ; Buffer，选择与预览缓冲区
    "i" '("缓冲区列表" . ibuffer)                  ; Ibuffer，缓冲区管理列表
    "k" '("关闭当前缓冲区" . kill-current-buffer)  ; Kill，关闭缓冲区
    "n" '("下一个缓冲区" . next-buffer)            ; Next，下一个
    "p" '("上一个缓冲区" . previous-buffer))       ; Previous，上一个

  (general-def my/help-map
    "k" '("解释按键" . helpful-key)                          ; Key，按键帮助
    "f" '("函数帮助" . helpful-callable)                     ; Function，函数帮助
    "x" '("命令帮助" . helpful-command)                      ; Execute，交互命令帮助
    "v" '("变量帮助" . helpful-variable)                     ; Variable，变量帮助
    "." '("光标处 Lisp 符号" . helpful-at-point)             ; At point，光标处符号
    "m" '("当前模式说明" . describe-mode)                    ; Mode，当前模式
    "b" '("当前有效键位" . describe-bindings)                ; Bindings，有效键位
    "w" '("查找命令按键" . where-is)                         ; Where is，查找命令绑定
    "a" '("按名称找命令" . apropos-command)                  ; Apropos，按名称查找
    "i" '("Emacs 手册" . info-emacs-manual)                  ; Info，Emacs 手册
    "g" '("自定义键位清单" . general-describe-keybindings))  ; General，自定义键位

  ;; Diagnostics：诊断；Messages 和 Debug 各保留一个入口。
  (general-def my/diagnostic-map
    "m" '("查看消息" . view-echo-area-messages)  ; Messages，消息日志
    "d" '("错误回溯" . toggle-debug-on-error))   ; Debug，错误回溯开关

  ;; Window，窗口布局；关闭显示区域不关闭其中的 Buffer。
  (general-def my/window-map
    "h" '("左侧窗口" . windmove-left)                   ; Left，沿用 Vim 向左键
    "j" '("下方窗口" . windmove-down)                   ; Down，沿用 Vim 向下键
    "k" '("上方窗口" . windmove-up)                     ; Up，沿用 Vim 向上键
    "l" '("右侧窗口" . windmove-right)                  ; Right，沿用 Vim 向右键
    "c" '("关闭当前窗口" . delete-window)               ; Close，关闭窗口
    "w" '("下一个窗口" . other-window)                  ; Window，循环切换窗口
    "s" '("上下拆分" . split-window-below)              ; Split，上下拆分
    "v" '("左右拆分" . split-window-right)              ; Vertical split，左右拆分
    "o" '("保留当前窗口" . delete-other-windows)        ; Only，只保留当前窗口

    "q" '("退出当前窗口或会话" . evil-quit)             ; Quit，当前窗口或会话
    "a" '("退出终端会话" . save-buffers-kill-terminal)  ; All，检查保存后退出会话

  ;; 标题跳转与代码块编辑在 Org 中调用；生成和目录更新使用原生命令。
  (general-def my/org-map
    "b" '("生成当前文档代码" . org-babel-tangle)    ; Babel，提取当前 Org 代码，不执行或加载
    "g" '("Org 标题跳转" . org-goto)                ; Go to，跳转标题
    "i" '("当前文件结构索引" . consult-imenu)       ; Index，预览结构索引
    "t" '("更新当前文档目录" . toc-org-insert-toc)  ; Table of contents，当前文档目录
    "s" '("编辑 Org 代码块" . org-edit-special))  ; Special，专用编辑界面

  ;; Jump，当前窗口可见文字定位；字符输入后按标签选择。
  (general-def my/jump-map
    "j" '("字符标签跳转" . avy-goto-char-timer)  ; Jump，字符跳转
    "l" '("可见行跳转" . avy-goto-line))        ; Line，行跳转

  ;; Search，全文搜索与结构选择；项目搜索依赖 Emacs 能找到 rg。

    "s" '("搜索当前缓冲区" . consult-line)       ; Search，搜索匹配行
    "r" '("项目或目录搜索" . consult-ripgrep)   ; Ripgrep，外部文本搜索
    "i" '("当前文件结构索引" . consult-imenu))  ; Index，预览结构索引

  (general-def my/command-map
    "," '("执行命令" . execute-extended-command))  ; Command，执行命令

  (general-def my/leader-map
    "," (cons "命令" my/command-map)     ; Command，命令
    "f" (cons "文件" my/file-map)        ; File，文件
    "b" (cons "缓冲区" my/buffer-map)    ; Buffer，缓冲区
    "h" (cons "帮助" my/help-map)        ; Help，帮助
    "d" (cons "诊断" my/diagnostic-map)  ; Diagnostics，诊断
    "w" (cons "窗口" my/window-map)      ; Window，窗口
    "q" (cons "退出" my/quit-map)        ; Quit，退出
    "o" (cons "文档与配置" my/org-map)   ; Org，文档与配置
    "j" (cons "跳转" my/jump-map)        ; Jump，屏幕内定位
    "s" (cons "搜索" my/search-map))     ; Search，搜索与索引

  ;; 普通／可视／motion 状态使用逗号；插入状态不占用逗号。

   :states '(normal visual motion)
   :keymaps 'override
   "," my/leader-map)

  ;; 仅普通模式的 s 改为 Avy；原替换字符操作可用 cl，其他状态不改。
  (general-define-key
   :states 'normal
   :keymaps 'override
   "s" #'avy-goto-char-timer)  ; Jump，字符标签跳转

  ;; 全局备用前缀访问同一份菜单，适用于插入状态及 Emacs 状态。
  ;; 原生 C-h 前缀保留，只增强其中几个具体帮助命令。
  (general-def
    "C-c ," my/leader-map        ; Leader，备用功能前缀
    "C-h k" #'helpful-key        ; Key，按键帮助
    "C-h f" #'helpful-callable   ; Function，函数帮助
    "C-h v" #'helpful-variable   ; Variable，变量帮助
    "C-h x" #'helpful-command))  ; Execute，交互命令帮助
#+end_src

这里通过 =my/leader-map= 复用菜单，不需要另外创建 =my/leader= 宏。
普通／可视／motion 状态使用逗号前缀，override keymap
降低被模式局部键位遮挡的概率；被覆盖的原操作在下面记录替代键。
文件等子分组采用命名 keymap，提示名称随绑定保存，配合 which-key 展示。
General 当前文档推荐这种 keymap 描述方式，而不是到处添加 =:which-key= 替换规则。

例如 =, f s= 保存，which-key 在 =,= 后显示“文件”等分组，
在 =, f= 后显示“保存文件”等命令。插入状态下用 =C-c , f s= 调用同一操作。
以后更换 leader，只需修改绑定根 keymap 的前缀；子菜单无需逐条修改。

**** General 怎么修改：对照示例

下面是修改指南，不是额外生效的配置。请修改上面对应的正式定义，
再保存、生成并重启；不要只修改说明示例，也不要直接改生成的 init.el。

| 正式定义中的内容                         | 含义                                     |
|------------------------------------------+------------------------------------------|
| general-def my/file-map                   | 编辑 f（file）分组的子键                  |
| "s" '("保存文件" . save-buffer)           | 子键 s、菜单说明、要执行的命令            |
| "f" (cons "文件" my/file-map)             | 把文件子菜单放到 leader 的 f 下           |
| general-define-key 中 "," my/leader-map   | 用逗号作为根前缀                         |
| :states '(normal visual motion)          | 只在这些 Evil 状态启用逗号               |
| "C-c ," my/leader-map                     | 备用前缀引用同一个菜单                    |

例如想把保存从 =, f s= 改成 =, f w=，在正式的 =my/file-map= 定义中，
把对应行的 ="s"= 改为 ="w"=，命令名保持不变：

#+begin_src emacs-lisp :tangle no
;; 修改前："s" '("保存文件" . save-buffer)
;; 修改后：
(general-def my/file-map
  "w" '("保存文件" . save-buffer))
#+end_src

想增加按键，就在对应分组的正式定义中增加“按键 + 描述和命令”；
想改提示文案，只改中文字符串；想改操作，就改右侧命令名。
需要新分组时先创建 sparse keymap，再定义子键，最后挂到 my/leader-map。
同一个分组内避免重复使用子键，否则后定义的绑定会覆盖前面的绑定。
删除或改名后请重启验证，因为重新执行部分代码可能保留旧绑定。

分组按英文记忆：f（File，文件）、b（Buffer，缓冲区）、h（Help，帮助）、
o（Org，文档）、d（Diagnostics，诊断）、w（Window，窗口）、q（Quit，退出）。
常用子键含义：s（Save，保存）、p（Path，路径）、m（Messages，消息；
窗口组中为 Maximize，最大化）、c（Close，关闭窗口）、a（All，全部）。
英文全称只用于这里的说明和代码注释，which-key 菜单描述保持中文。
这些是记忆提示，不是所有 Emacs 命令都使用相同缩写，具体以菜单和命令名为准。
子键也优先使用能联想到命令的字母，遇到已有绑定时保留旧入口并明确说明新键。

*** Leader 与键位取舍

逗号 =,= 作为普通／可视／motion 状态的 leader，插入状态保留普通逗号输入。
逗号原有的反向重复字符查找被 leader 覆盖，本阶段不提供替代键；正向重复仍是 =;=。
原生 =C-h= 帮助入口保留；插入状态或 Emacs 状态使用 =C-c ,= 备用入口。
Help、Dired 等模式可能有更高优先级局部键位，先尝试备用前缀；手动启动后确认冲突。
第二阶段将普通模式 =s= 用于 Avy，原来的替换字符操作可用 =cl=；
可视与插入状态不新增 s 的 Avy 绑定。
不采用参考文件把点号 =.= 改成跳转的绑定，以保留 Vim 重复编辑功能。

=C-c ,= 是备用 leader，后接同样的子键；它绑定的是 keymap，
不是单个交互命令，因此没有单独的 M-x 函数名。
例如 =, o b= 与 =M-x org-babel-tangle RET= 调用同一命令，
=, o t= 与 =M-x toc-org-insert-toc RET= 也一样。
想知道其他模式中某个键对应什么命令，可用 =, h k=；
反过来根据命令查快捷键，用 =, h w=（=M-x where-is RET=）。

例如 =, h k= 进入按键查询后，输入 =, f s= 可以查看保存命令的绑定。
=,,,= 是普通／可视／motion 状态下连续输入三次逗号，不需要同时按键；
插入状态仍可用原生 =M-x=，或者备用前缀后再输入两个逗号：=C-c , , ,=。
配置生成使用 =, o b= 或 =C-c C-v t=，也可执行 =M-x org-babel-tangle RET=，
作用于当前 Org 缓冲区，建议先保存源文件；输出由当前文档的 :tangle 属性决定，
不固定源文件名，也不会额外保存源文件、执行代码块或加载生成结果。
目录随保存自动更新；需要立即更新时按 =, o t=，或执行 =M-x toc-org-insert-toc RET=，
作用于当前带 TOC 标签的 Org 文档，不需要包装函数或固定路径。

=, f u= 会重新读取磁盘内容，可能替换缓冲区里未保存的修改；保留 Emacs 的确认提示，
确认前先判断是否要保存当前修改。它与未来自动刷新未修改缓冲区的功能不同。
=, f p= 用于当前正在访问文件的缓冲区，复制绝对路径到 kill ring，
系统剪贴板是否同步取决于 Emacs 的图形／终端环境；无文件的缓冲区会提示不能复制。
=, o s=（=M-x org-edit-special RET=）在 Org 代码块内调用，进入对应语言的专用编辑缓冲区，
完成后用 =C-c '=（=M-x org-edit-src-exit RET=）返回；
返回只更新 Org 中的代码文字，不会执行或生成配置。

等搜索／替换方案确定后再安排。其他候选键位不添加。
